# W16 · 前沿 + 毕业答辩（课件）

> 对应阅读: Ch17 Frontiers (PDF p.481–502)：GVF (p.481)、Options (p.483)、Observations vs State (p.486)、Reward Design (p.491)、Future (p.497)
> 里程碑: 最终演示 + 问答 + 提交（repo / 报告 / 视频）
> 配套笔记: 建议 `Chapter-17-Frontiers-and-Recap.md`（课程收尾）

## 学习目标

1. 能讲清 3 个前沿方向（GVF、Options、观察 vs 状态）各解决什么问题；
2. 用 10 分钟讲清"做了什么、怎么做的、做得怎么样"；
3. 准备好 8 类高频答辩问题；
4. 按 rubric 完成自评并提交全部材料。

## 前沿速览（各 5 分钟能讲清）

| 方向 | 问题 | 一句话方案 |
|---|---|---|
| **GVF**（General Value Functions, p.481） | 只学"到达目标的价值"太窄 | 学**任意**条件期望（"距墙多远""还剩多少电池"），一次训练多个辅助信号 |
| **Options**（Temporal Abstraction, p.483） | 动作粒度太细（步级） | 学"宏动作"（subpolicy + 终止条件 + 初始集），分层决策 |
| **Observations vs State**（p.486） | 真实环境只给部分观察 | 信念状态 / POMDP 视角；课程里表格法默认全观察，这是它的边界 |

→ 答辩时若被问"你的方法的局限"，这三条都是标准答案。

## 演示脚本（10 分钟）

| 时间 | 内容 | 要点 |
|---|---|---|
| 0–1' | 项目名 + 目标 + 验收线 | 对应开题的"验收标准" |
| 1–2' | 架构图 | 指出 3 个关键组件 + 各自用哪章方法 |
| 2–8' | 现场演示 2–3 个场景 | 每场景：输入→行为→结果；**故意演示一次失败 + 恢复/降级** |
| 8–9' | 数据/指标 | 胜率/回报曲线/消融对比，给一个数字 |
| 9–10' | 总结 + 局限 + 下一步 | 诚实 > 完美；局限用 W16 三条前沿包装 |

**录视频**：关键步骤不剪辑；失败也要录进报告（加分项）。

## 高频答辩问题（8 类，各备 30 秒口答 + 1 个证据）

1. **为什么**：为什么选这个算法/环境？（对比 1 个替代方案的代价）
2. **正确性**：你的指标怎么测的？seed 几个？曲线是训练的还是 test 的？
3. **鲁棒性**：reward 改 10% / 环境噪声加大 / 训练中断续训，各会怎样？
4. **性能**：steps/s 多少？瓶颈在数据、网络还是环境？
5. **安全/失败**：策略最坏情况做什么？有没有"不可接受动作"的拦截？
6. **架构**：哪个组件设计得最别扭？为什么？
7. **复现**：陌生人 30 分钟能跑起来吗？（现场翻 README）
8. **反思**：重做一遍会改什么？（准备 2 条，1 技术 1 流程）

## 报告结构（≤8 页）

1. 摘要（100 字，含 1 个关键数字）
2. 目标与验收标准（引用开题）
3. 系统架构 + 方法选型（对应课程章节）
4. 实现要点 + 关键代码片段（≤3 段）
5. 实验与数据（场景、指标、消融、失败案例）
6. 风险与未完成项（诚实清单）
7. 结论与展望（用 GVF/Options/POMDP 包装局限）
8. 参考文献与致谢（含开源包 + 许可证）

## Rubric 自评表

| 维度 | 权重 | 自评(1-5) | 证据（repo 路径/截图/曲线） |
|---|---|---|---|
| 功能完整性（必做项全过） | 35% | | |
| 实验设计与曲线质量（seed/消融/test 分离） | 25% | | |
| 代码质量（结构/README/可复现） | 20% | | |
| 文档与答辩（报告/视频/回答质量） | 20% | | |

> 加权后 < 80 → 按开题的降级方案返工一次，再自评。

## 常见坑

- 演示依赖"只有我知道的本地状态"（模型/数据没进 repo）→ 把"从零复现"当硬验收。
- 训练没完成就上台 → 先跑 pilot，给"最小可演示版本"留缓冲。
- 曲线全是训练曲线（没 test 分离）→ 评审一眼看穿；test 每 N 步 5 局平均。
- 把"没做完"说成"做了" → 一戳就穿；未完成项写进报告反而加分。
- 答辩冷场时不会收尾 → 准备一句"这个点我们实测过 X，结论是 Y"的万能句。

## 自测

1. 你的 30 秒电梯陈述（项目 + 能力 + 1 个数字）？
2. 8 类问题里最没底的是哪类？本周补什么证据？
3. GVF / Options / POMDP 三条，哪条最适合包装你项目的局限？
4. 提交物 checklist 逐项打勾（repo/报告/视频/README/曲线/引用）？

### 参考答案（示例）

1. "四子棋 MCTS AI：1000 次迭代下胜率 78%，训练零数据，代码 300 行可复现。"
2. 例：鲁棒性最没底 → 本周补"噪声 +20%"实验 + 前后胜率对比。
3. 例：项目是单任务导航 → 用 GVF 包装"可扩展多辅助信号"为下一步。
4. 对照"报告结构 + 演示脚本 + 自评表"三节，逐项核对并截图存证。
