# W16 · 毕业项目答辩（课件）

> 对应阅读: 项目相关章节回顾（按你的选题）
> 里程碑: 最终演示 + 问答 + 提交（repo / 报告 / 视频）
> 配套笔记: 全课程笔记的最终整合（建议写 `Chapter-16-Course-Recap.md`）

## 学习目标

1. 用 10 分钟讲清"做了什么、怎么做的、做得怎么样"；
2. 准备好 8 类高频答辩问题；
3. 按 rubric 完成自评并提交齐全部材料。

## 演示脚本（10 分钟）

| 时间 | 内容 | 要点 |
|---|---|---|
| 0–1' | 项目名 + 目标（一句话） | 对应开题的"验收标准" |
| 1–2' | 系统架构图 | 指出 3 个关键节点/接口 |
| 2–8' | 现场演示 2–3 个场景 | 每个场景：输入 → 系统行为 → 结果；**故意演示一次失败 + 恢复** |
| 8–9' | 数据/指标 | 成功率、耗时、与基线（Nav2/规则）对比 |
| 9–10' | 总结 + 不足 + 下一步 | 诚实 > 完美 |

**录视频要求**：全程不剪辑关键步骤；失败也要录进去并在报告里分析（加分项）。

## 高频答辩问题（8 类）

1. **为什么**：为什么用 BT/Nav2/这个规划器？（对比 1 个替代方案的代价）
2. **正确性**：你的定位/规划误差怎么测的？数据从哪来？
3. **鲁棒性**：传感器丢帧 / 目标丢失 / 通信中断，系统分别怎么办？
4. **性能**：关键回路的频率与延迟？瓶颈在哪？
5. **安全**：什么情况下系统会主动停下来？急停链路是什么？
6. **架构**：这个包拆得对吗？哪个接口设计得最别扭？为什么？
7. **复现**：陌生人 30 分钟能跑起来你的 demo 吗？（现场看 README 质量）
8. **反思**：重做一遍会改什么？

> 准备方法：每题写"30 秒口答 + 1 个证据（日志/截图/命令）"。

## 报告结构（≤8 页）

1. 摘要（100 字）
2. 目标与验收标准（引用开题）
3. 系统架构 + 接口清单
4. 实现要点（关键决策 + 取舍，附最小代码片段）
5. 实验与数据（场景、指标、失败案例）
6. 风险与未完成项（诚实清单）
7. 结论与展望
8. 参考文献与致谢（含所用开源包 + 许可证）

## Rubric 自评表

| 维度 | 权重 | 自评(1-5) | 证据（repo 路径/截图） |
|---|---|---|---|
| 功能完整性（必做项全过） | 40% | | |
| 代码质量（结构/命名/测试/README） | 25% | | |
| 文档与演示（报告/视频/可复现） | 20% | | |
| 创新性（加分项/对比实验） | 15% | | |

> 加权后 < 80 → 按 W15 降级方案返工一次，再自评。

## 常见坑

- 演示依赖"只有我知道的环境状态"（地图没随 repo 走、参数在本地）→ 把"从零复现"当成硬性验收。
- 演示时网络/API 不稳定 → 准备离线 fallback（规则控制器）并提前说明。
- 把"没做完"说成"做了"→ 答辩现场一戳就穿；未完成项写进报告反而是加分。
- 视频里键盘敲命令打字太快 → 演示脚本 + 预启动（但关键命令要现场敲）。

## 自测

1. 你的 30 秒电梯陈述是什么？（项目名 + 能力 + 一个数字）
2. 8 类问题里你最没底的是哪一类？本周补什么证据？
3. 如果现场演示失败，你的 30 秒应变话术是什么？（例："我复现一下刚才的触发条件……"）
4. 全部提交物 checklist 是否逐项打勾？（repo / 报告 / 视频 / README / 开源许可清单）

### 参考答案（示例）

1. "自主导航服务机器人：自建地图上 90% 成功率完成 3 段任务链，单次平均 12 秒。"
2. 例：鲁棒性最没底 → 本周补"断网 5 秒"实验 + 恢复日志。
3. "我复现一下刚才的触发条件，正好可以看到系统的降级路径……"（顺势展示恢复机制，比道歉有效）。
4. 见"报告结构 + 视频要求 + 自评表"三节，逐项核对。
