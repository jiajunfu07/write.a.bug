# W15 · 毕业项目开题（课件）

> 对应阅读: 按所选方向 —— M Ch11（空中）/ Ch12（DIY 实车）/ Ch13（测试与 CI-CD）/ Ch15（DRL）
> 里程碑: 开题报告（1 页）+ 评审
> 配套笔记: 按方向补写对应章节笔记

## 学习目标

1. 从 5 个选题中选定 1 个并说清"为什么是它"；
2. 写出可执行、可验收、可评审的 1 页开题报告；
3. 把所选方向的"核心章节"列入 W15–W16 的阅读计划。

## 选修方向速览

### A. 空中机器人（M Ch11）

- 栈：PX4 + Gazebo + MavLink；`ros2 launch px4_sitl` 起仿真。
- 关键话题：`/fmu/out/*`（遥测）、offboard 控制 `px4/utdr`（以书为准）、经纬度 ↔ 本地坐标。
- 演示：自动起飞 → 悬停 → 航点航线 → 降落。

### B. DIY 移动机器人（M Ch12）

- 栈：Raspberry Pi + 差速底盘 + 电机驱动 + 2D LiDAR。
- 关键链路：驱动 → `/wheel_cmd`/`/joint_states` → 里程计 → `/odom`；LiDAR → `/scan`。
- 演示：实车遥控 + 里程计 + （加分）实车 SLAM/Nav2。
- 无硬件替代：用 Gazebo + 虚拟"RPi 节点"（发布同样的接口）模拟全链路。

### C. 测试与 CI/CD（M Ch13）

- 栈：GTest + `colcon test`（ament_cmake_gtest）+ GitHub Actions。
- 关键产物：单元测试（纯逻辑）、节点级测试（`ros2 pytest`/gtest 集成）、CI 徽章。
- 演示：push 代码 → 云端自动 build + test 的完整记录。

### D. 深度强化学习（M Ch15）

- 栈：Gymnasium + 训练框架（SB3/自定义）+ 仿真环境。
- 关键概念：state/action/reward 设计、训练/评估分离、sim2real 差异。
- 演示：策略从"乱撞"到"稳定到达"的对比视频 + 与 Nav2 的指标对比。

## 开题报告模板（1 页）

1. **项目名 + 一句话目标**（能做什么、做到什么程度）
2. **系统架构图**（节点/包/话题/action 连线；硬件或仿真标注清楚）
3. **技术栈与依赖**（包 + 版本 + 硬件清单）
4. **里程碑**（4 个，各带"验收标准"：可运行的命令/截图/指标）
5. **风险与预案**（≥3 条：风险、概率、缓解措施）
6. **评分量规自评**（功能 40 / 代码 25 / 文档 20 / 创新 15，给自己定目标分）
7. **引用与素材**（书本章节、参考项目、许可证）

## 评审检查清单（评审人视角）

- [ ] 目标可验收（有命令/指标，不是"大概能跑"）
- [ ] 架构与已学知识对齐（没有无理由的黑盒）
- [ ] 里程碑粒度合适（W16 前能完成 3 个 + 演示）
- [ ] 风险诚实（没写"无风险"）
- [ ] 范围克制（必做 vs 加分项分清）

## 常见坑

- 开题写得像"论文展望"：没有验收标准 → 评审不通过。
- 同时选 A+B（又飞又跑）→ 范围爆炸；二选一 + 一个加分项。
- 硬件依赖没备货/没替代方案 → W16 卡在物流；"无硬件替代链路"必须写进预案。
- 忽略依赖版本（Gazebo/ROS/驱动）→ 复现不了；开题里钉死版本矩阵。

## 自测

1. 你的项目"最小可演示版本"是什么？（1 句话 + 1 条验收命令）
2. 列出项目里 3 个你"还没完全掌握"的技术点 + 计划用什么材料补？
3. 如果 W15 只完成 50%，W16 演示什么？（降级方案）
4. 你的项目用到了哪些 action？哪些 topic？（画出接口清单）

### 参考答案（示例）

1. "Nav2 + BT 在自建 Gazebo 世界里完成 A→B→回窝"；验收：`ros2 action send_goal /navigate_to_pose ...` 成功 3/3 次。
2. 例：SLAM 参数 → M Ch8 + 官方文档；BT Navigator → M Ch7 示例代码；DRL 训练 → M Ch15 + 官方 Gymnasium 文档。
3. 演示"单点导航 + 手动恢复行为"，并给出失败点与原因分析（评审看重诊断能力）。
4. 接口清单示例：action: NavigateToPose；topic: /scan /odom /map /cmd_vel；service: /get_costmap。
